# E4981A 接触变化后读数滞后排查

## 现场信息与结论边界

用户确认生产机没有启用平均。不能用开发机配置中的平均开关解释生产现场；本次保留一次测试只触发一次，不增加软件平均、稳定采样或固定等待。

已确认软件存在响应错位风险：TCP 查询超时或取消后，原先连接和接收缓冲继续复用。SCPI 响应没有请求编号，迟到的空夹具读数可能被当成接触后的结果，迟到的产品读数也可能被当成断开后的结果。版本 `1731830` 在恢复单次测试时移除了查询中断后的响应同步保护。

这是代码确认的缺陷，尚不能仅凭症状断言它就是生产机本次故障的唯一根因。需对照仪表面板和现场 TX/RX 日志，区分仪表自身读数滞后、响应错位及失败后显示旧值。

根据 [Keysight 编程手册第 163 页](https://www.keysight.com/cm/en/assets/9018-02357/programming-guides/9018-02357.pdf)，BUS 模式下 `*TRG` 在测量完成后返回结果，无需再发 `FETC?`；当前代码没有双重查询。

## 修复后的行为

- 在途 TCP 命令超时/取消时断开并清空旧连接，要求重新连接。仅清空已经收到的字节不能阻止尚在传输中的迟到响应。
- 发送新命令前发现残留响应就报错断开，禁止将它作为下一次结果。等待命令锁期间的取消不影响当前正常查询。
- 手动单次测试与自动生产共用单次触发路径；开始测量或测量失败时清除旧电容、损耗、BIN 和原始结果，避免旧结果看似本次有效。
- 参数下发后回读 `TRIG:SOUR?`、`INIT:CONT?`、`AVER?`，记录仪表实际值。触发源、连续触发准备状态或平均开关不符合本次配置时，禁止触发并断开连接。
- 手动发送 SCPI 后使参数缓存失效，下次正式测试重新同步仪表设置。
- 每条 RX 日志增加对应命令和往返耗时，便于核对响应关系。

## 已完成的验证

将修改前 HEAD 的原始 TCP 客户端提取到 `codex-tmp/e4981a-stale-repro`，在关闭平均的模拟环境中让第一次查询超时，再延迟返回它的响应，实际复现：接触测试（当前 400 nF）收到旧的 0.003 nF；断开测试（当前 0.003 nF）收到旧的 400 nF。此实验验证响应错位机制，并不代表已采集到生产机真实故障日志。

`tests/TestStationFlowChecks` 使用本机回环 TCP 仪表模拟器，不连接运动卡或真实仪表：

- 平均关闭时，400 nF 与 0.003 nF 接触/断开切换；自动测试与实际单次测试按钮每次只触发一次。
- 缺失、半包、迟到、多余响应，通讯超时/取消，清洁重连和正常分包。
- 失败后清除旧显示；实际状态回读、不一致时禁止触发；原有参数缓存、BIN/D 判定、分料、复测及联锁回归。

## 现场复核

1. 使用更新后的程序重新连接仪表，保持生产机平均关闭及原有测量参数。
2. 空夹具、稳定接触约 400 nF 产品、移开产品，分别点击一次单次测试，每次等待完成并对照仪表自身屏幕。
3. 保留三次测试的 TX/RX 日志及第一次参数回读。正常平均关闭应记录 `TRIG=BUS，INIT:CONT=1，AVER=0`，每轮只有一组 `*TRG` 和对应 RX。
4. 如果出现超时/残留响应，程序应断开并将电容显示为 `-- nF`，重新连接后测试。若仪表面板本身仍滞后，则继续检查现场触发状态、接触、量程、测试线及夹具补偿，不能据此认定软件修复已解决实机故障。
